# Advisra · 明策 — 项目说明

> 一款面向财富管理一线从业者的单文件 AI 工作台。
> 在线访问：https://zjszjs007.github.io/Advisra/

---

## 一、问题

理财经理每天被三类事打断，而这三件事恰好都不产生专业价值。

| 环节 | 原本怎么做 | 麻烦在哪 |
|---|---|---|
| 客户问行情 | 切三四个 App 查数据，凭记忆组织话术 | 一条回复 8–15 分钟；说得有没有底气，全看个人经验 |
| 出配置方案 | 手工拉历史业绩、做 PPT、算比例 | 一户 60–90 分钟；模板化严重，客户一眼看穿 |
| 讲保险 | 翻计划书，用 Excel 手算 IRR | 增额寿要算 40 年现金流，手算易错；算错即对客承诺，属合规事故 |
| 发出去之前 | 凭感觉判断会不会踩红线 | 宁可不说，也不敢说 |

**一天里真正的专业判断只占 20%，剩下 80% 花在找数、算数、组织语言、怕出错上。**

更需要正视的是：这不是效率问题，而是**转化问题**。客户问「我的基金跌了怎么办」，从业者回得慢、回得空、回得心虚，客户就会换一个人问。

---

## 二、方案

把上述四个环节压缩进一个界面，并且做到「每句话都有依据、每次输出都先过合规」。

### 四个核心场景

**1. 客户问答 — 把 10 分钟压到 30 秒**

固定四段式结构：**结论 → 依据 → 对这位客户意味着什么 → 建议动作**。

关键在于第三段引用该客户真实持仓，而非泛泛而谈：

> 「林女士，您的组合权益仓位 33%，本月回撤贡献约 -1.9 万，约占总资产 0.4%。债券和理财部分对整体是正贡献，组合波动明显小于指数。」

每个数字旁有「溯源」按钮，可追到数据时间戳与来源。

**2. 配置方案 — 从 90 分钟到 3 分钟**

按 C1–C5 风险等级确定性计算五账户比例（要花的钱 / 保本升值的钱 / 生钱的钱 / 对冲的钱 / 保命的钱），并按年龄、流动性需求做二阶修正。

输出：环形图 + 偏离诊断 + 按适当性过滤的产品池 + 3 组客户追问应对话术 + 一页纸建议书。

**3. 保险测算 — 双通道设计**

| | 通道 A：精算 | 通道 B：快速测算 |
|---|---|---|
| 前提 | 导入条款 PDF / 现金价值表 | **什么都不用传** |
| 数据 | 合同附表真实数据 | 险种经验参数（可调） |
| 标注 | 无 | 琥珀标签「估算 · 不可对客」 |

之所以设两个通道，是因为真实场景里客户常常当场就问、材料却还没到手。若必须先拿到 PDF 才能算，工具在最需要它的时刻反而不可用。

**4. 合规闸门 — 从事后追责到事前拦截**

粘贴拟发送话术，命中处**原句标红**，给出规则编号与改写建议。三层机制：L1 硬规则 → L2 语义检测 → L3 人工确认留痕。

问「你直接告诉我买哪只能赚钱」，系统不生成推荐，而是识别为越界，转为投教式回应并标注「已自动拦截」。

### 三个工程决定

**① 数值绝不交给模型算**

配置比例、IRR、回本年限均由独立计算引擎产出。IRR 用二分法求解现金流，保费按保单年度**期初**缴纳。已做独立复核：

```
5 年交 20 万，第 10 年现价 1,015,000
Python 独立计算 → 10 年 IRR 0.1862%
页面显示        → 0.19%   ✓
```

**② 宁可不给，也不猜**

- 现金价值表缺保费信息 → 不自动推算，提示手工填写
- IRR 超 6%（远超增额寿 1.5–3.5% 行业区间）→ 弹出警告标明「极可能是保费填错」
- 扫描件 PDF 无文本层 → 明确提示「无法抽取」并给三条替代路径，而非假装成功

**③ 单文件、零依赖**

`docs/index.html` 一个文件 2.9MB，双击即用。pdf.js 内联，离线可跑。代价是体积，换来的是零配置——不需要 npm install、不需要起服务器、不需要联网。

## 三、边界

这一节比前两节更重要，因为它决定了这个作品现在能用在哪、不能用在哪。

### 数据边界

**全部为本地模拟数据，无一条来自外部数据源。**

- 5 位客户、10 个产品、4 组问答模板，均为手写静态数据
- 行情点位、涨跌幅、估值分位为示意值
- 保险条款与现金价值表为虚构样本，非真实产品费率

**MCP 在本项目中没有实际调用。** 会话中 Wind Alice 虽显示已连接，但原型未接入。原因有三：

1. 项目定位是验证**产品形态与交互逻辑**，不是验证数据准确性
2. 客户持仓属个人金融信息，不可能进演示环境
3. 一旦依赖外部服务，「单文件离线可跑」这个特性就消失了

### 能力边界

| 不做 | 原因 |
|---|---|
| 不做荐股、不做买卖点提示 | 触及投顾牌照与《证券法》红线 |
| 不做收益承诺、不做业绩预测 | 资管新规后属禁区 |
| 不直接面向 C 端客户 | 定位是 B 端工具，避免与机构争夺客户关系 |
| 不替代 CRM / 核心系统 | 做上层智能层，通过 API 对接 |
| 不含 OCR | 扫描件需先外部识别 |

### 已知限制

- 客户问答为关键词匹配的预设，未接入真实大模型
- 快速测算的经验参数为行业公开区间估算，需以真实样本校准
- 精算准确性依赖现金价值表本身正确，导入后建议手工核对 2–3 个年度
- 首次加载 3MB，实际传输约 700KB–1MB（Pages 有 gzip）

### 合规声明

本项目为**产品原型演示**，不构成任何投资建议、收益承诺或保险销售材料。

所有测算结果仅供内部参考。任何对客输出必须基于合同附表的真实现金价值数据，并经从业者本人确认。实际用于业务前，须由所在机构合规与法务部门逐条复核适用监管要求。

## 落地路径

若要推进到可用状态，优先级如下：

| 阶段 | 动作 | 解决什么 |
|---|---|---|
| 第一步 | 行情接 Wind Alice（MCP） | 回复中的点位、估值从写死变为真实数据 |
| 第二步 | 企业客户接企查查 / 启信慧眼（MCP） | 客户是企业主时，拉工商、股权、涉诉信息，判断真实风险承受力 |
| 第三步 | 问答接真实大模型 + 机构知识库 RAG | 从关键词匹配升级为语义理解 |
| 第四步 | 私有化部署 + 合规预审 | 客户数据不出域，获得机构准入门票 |
