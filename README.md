# Advisra · 明策

> 面向财富管理一线从业者的 AI 工作台 —— 让理财经理在对客沟通时，表现得像一个有 10 年经验的资深投顾。

**Advisra** = *advisor* + *-ra*（拉丁语系名词后缀），读作 `/ədˈvaɪzrə/`。
中文名**明策**：「明」是把话说清楚、把依据讲明白，「策」是配置与策略。

## 这是什么

一个**单文件、零依赖、可离线运行**的交互原型。双击 `prototype/advisra.html` 就能用，不需要安装、不需要启动服务器、不需要联网。

它解决的是财富管理从业者每天被反复打断的三个动作：

| 痛点 | 工具做什么 |
|---|---|
| 客户随时来问行情，答得慢、没底气 | 生成「结论 → 依据 → 对这位客户意味着什么 → 建议动作」四段式回复，每个数字可溯源 |
| 配置方案千人一面，客户一眼看穿 | 按风险等级 + 年龄 + 流动性确定性计算五账户比例，配套产品池与沟通脚本 |
| 保险讲不清 IRR 和回本 | 导入条款 PDF 与现金价值表，算出合同口径的真实 IRR |

## 功能模块

### 首页概览
今日待办按客户价值与时效排序，市场速览，本周合规拦截统计。

### 客户档案
5 位演示客户画像、持仓结构可视化、**AI 自动诊断**（权益偏离基准 / 闲置现金过高 / 保障缺口 / 适当性错配）。

### 客户问答
输入客户问题，生成四段式结构化回复。每个数字带「溯源」按钮，底部自动叠加合规提示。

> 试试点「你直接告诉我买哪只能赚钱」——它不会生成推荐，而是识别为越界问题，转为投教式回应并标注「已自动拦截」。

### 配置方案
按 C1–C5 风险等级计算五账户（要花的钱 / 保本升值的钱 / 生钱的钱 / 对冲的钱 / 保命的钱）比例，并按年龄、流动性需求做二阶修正。

输出：环形图 + 偏离诊断 + 产品池（按适当性过滤）+ 3 组客户追问应对话术 + 一页纸建议书。

### 保险测算 ⭐ 双通道

这是本项目最核心的模块，两条通道应对两种现实场景：

| | **通道 A：精算** | **通道 B：快速测算** |
|---|---|---|
| 前提 | 已导入条款 PDF / 现金价值表 | **什么都不用传** |
| 数据 | 合同附表真实数据 | 险种经验参数（可调） |
| 输出 | 逐年度 IRR、回本、身故赔付、贷款额度 | 同上，估算区间 |
| 标注 | 无 | 琥珀标签「估算 · 不可对客」+ 警示条 |

**通道 A 支持的输入格式：**

- **条款 PDF** → 自动抽取 13 项要素（产品名、条款编号、备案号、投保年龄、保险期间、交费期间、保额递增率、犹豫期、等待期、保单贷款比例、减保限制、身故责任）
- **xlsx / csv** → 识别「保单年度 + 现金价值」结构，自动定位表头、识别多组缴费期列
- **同一份 PDF** → 若条款内嵌现金价值表，自动识别并载入

**通道 B 支持的险种：** 增额终身寿、养老年金、定期寿险（改算保障杠杆）

### 合规闸门
粘贴拟发送话术，实时检测。命中处**原句标红**，列出规则编号与层级，并给出 AI 改写建议。

三层机制：L1 硬规则拦截 → L2 语义检测 → L3 人工确认留痕。

## 技术实现

### 单文件架构

生产文件 `advisra.html` 由 `prototype/parts/` 下的 9 个片段拼接而成：

```
parts/
├── 00_head.html        # 样式与页面骨架
├── 01_data.html        # 演示数据（客户、产品池、问答库）
├── 02_app.html         # 路由、工作台、客户档案、问答
├── 03_alloc.html       # 配置方案
├── 04_ins.html         # 合规闸门 + 事件总线
├── 05_pdfjs.html       # pdf.js 内联（构建产物，勿手工编辑）
├── 06_engine.html      # 条款解析 / 表格识别 / IRR 引擎
├── 07_insv2.html       # 保险测算 - 精算通道
└── 08_quickcalc.html   # 保险测算 - 快速通道
```

重新构建：

```bash
node build-pdfjs.cjs   # 仅在需要更新 pdf.js 时运行
node build.cjs         # 拼接生成 advisra.html
```

### 几个关键工程决定

**1. 数值一律不交给模型算**
配置比例、IRR、回本年限都由独立计算引擎产出。IRR 用二分法求解现金流，保费按保单年度**期初**缴纳。可用 Python 独立复算验证：

```
5 年交 20 万，第 10 年现金价值 1,015,000
→ 10 年 IRR 0.1862%   页面显示 0.19%  ✓
```

**2. 推理数据必须显式标注来源**
快速通道的结果带琥珀标签和红色警示条，与精算通道在视觉上严格区分，避免误用于对客承诺。

**3. 宁可不给，也不猜**
- 现金价值表缺少保费信息时，不自动推算，提示用户手工填写
- IRR 超过 6%（远超增额寿 1.5–3.5% 的行业区间）时，弹出警告标明「极可能是保费填错」
- 扫描件 PDF 没有文本层时，明确提示「无法抽取」，并给出三条替代路径，而非假装解析成功

**4. pdf.js 内联，代价是体积，换来的是零配置**
`file://` 协议下 Blob worker 与动态 import 都受 CORS 限制。解决方案是先把 worker 全局注入主线程（`globalThis.pdfjsWorker`），让 fake worker 直接可用；在 http(s) 环境下才启用后台 worker。

## 已知限制

- 演示数据全部为模拟，客户、行情、产品池均非真实
- 客户问答为关键词匹配的预设，未接入真实大模型
- 扫描件 PDF 需先做 OCR，工具本身不含 OCR 能力
- 精算通道的准确性依赖现金价值表本身正确，导入后建议手工核对 2–3 个年度
- 经验参数（通道 B）为行业公开区间估算，需以真实产品样本校准
